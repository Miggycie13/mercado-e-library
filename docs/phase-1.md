Mercado E-Library is a shared catalog of public-domain books. A website and an Android app both use one API on port 4000 and one SQLite database reached through Prisma.

A guest needs no account. A guest can open the catalog, open a book, download up to 5 distinct books, and ask the librarian. A guest cannot save a book to My Library or Favorites. Downloading a book that was already downloaded does not take another slot. The server enforces the limit.

A registered reader signs up with a name, an email, and a password, then is signed in. Login checks the email and password. Logout ends the session and clears the saved token. A reader can download up to 10 distinct books and can keep My Library and Favorites. Those lists live on the shared server, so the website and Android read the same rows. The role user is a reader. The role admin opens the admin desk. The demo reader is reader@elibrary.local and the demo admin is admin@elibrary.local.

The database has five tables. User stores the account: id, a unique email, name, password hash, role, and the time it was created. Book stores the catalog record: id, title, author, category, year, language, description, an optional source address, and the created and updated times. Title and author together are unique. DownloadLog stores each download with the book, an optional user, an optional guest key, an optional address, and the time. A guest download stores the guest key and leaves the user empty. Favorite stores one favorite per user and book. LibraryItem stores one My Library row per user and book. A user may have many downloads, favorites, and library rows. A book may appear in many of those rows. Deleting a user or a book removes the related rows. A guest can write only to DownloadLog. Favorite and LibraryItem require an account.

The librarian runs inside the API. The website and Android send the conversation to POST /api/ai/chat. The agent uses three tools on the live catalog: search_books, get_book_details, and add_to_my_library. A question searches, then loads a record, before the reply states a title or a description. A request to save a book does not write during the chat. The reader must accept it through POST /api/ai/confirm. Confirm writes a LibraryItem and a Favorite. Cancel writes nothing. A guest cannot confirm a save.
